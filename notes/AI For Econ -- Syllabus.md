# **Overview**

This syllabus outlines six study group sessions on using AI tools in academic economics. Topics were initially created by Claude, and then refined by Elira Kuka and XXX  
   
   
**Sessions 1 and 2: Coding, Data Analysis, and Vibe Coding**  
The single highest-value use of AI for most economists. Covers writing and debugging code in any language, automating repetitive data tasks, and the emerging practice of ‘vibe coding’ — building complete analytical tools from plain English descriptions alone. This session also naturally introduces Claude Code and agentic tools, since these are most obviously useful for coding tasks.

We can do this in two sessions, given it's the most complicated but probably useful stuff.  
 

## **Key Tasks Where AI Can Help**

General AI-use:  
•   	Writing and debugging Stata, R, and Python code from plain-English descriptions  
              •   	Automating repetitive data tasks: cleaning, reshaping, labeling, merging  
•   	“Vibe coding”: building complete econometric tools without writing a single line of code  
•   	When to trust AI code — and how to verify it doesn’t just look right

Specific programs that can help some of the above:  
•   	Using **Claude Code** in the terminal to autonomously run code, read output, and iterate  
         •   	Using Claude Code to create replication packages  
         •   Autonomous applications with large datasets, and private or secure datasets  
•   	Using **Git** with Claude Code: version control without needing to learn Git commands  
•   	Using **VS Code** with AI-integration (anaconda and jupyter lab with python)  
   
*Source: Korinek (2025) NBER WP 34202; Panjwani (@aniketapanjwani) on X; Goldsmith-Pinkham (2024)*  

   
**Session 3: Finding and Collecting Data**  
AI dramatically lowers the barrier to building your own datasets. This session covers identifying data sources, writing scraping scripts, and using agentic tools to automate multi-step data collection — a natural place to discuss how agents differ from simple chatbots.  
 

## **Key Tasks Where AI Can Help**

•   	Identifying available datasets for a research question — and checking AI’s suggestions  
•   	Agentic scraping: describe target in English and let Claude Code write \+ run the scraper  
•   	Pulling data from APIs (FRED, Census, World Bank, BLS) without knowing API syntax  
•   	Parsing and cleaning PDFs, HTML tables, and unstructured text at scale  
•   	Building custom data retrieval agents that run autonomously  
•   	Multimodal data collection: using AI to evaluate images, videos, and audio for research   	•   	How best to handle AI data collection tools for replicability?  
   
*Source: Korinek (2025) NBER WP 34202, Section 4.1; Panjwani on agentic scraping (X, 2025\)*  
   
   
**Session 4: Teaching: Slides, Exams, and Student Feedback**  
AI can significantly reduce the overhead of course preparation and student assessment. This session covers creating and updating Beamer slides, generating assessments, and providing scalable feedback.  
 

## **Key Tasks Where AI Can Help**

•   	Creating Beamer slide skeletons from paper sections, bullet points, or lecture notes  
•   	Updating existing slides when incorporating new papers or empirical results  
•   	Writing exam questions, problem sets, and answer keys from course materials  
•   	Generating personalized written feedback on student work at scale  
•   	Using Claude Projects for each course: uploading syllabus and materials as persistent context  
•   	Explaining difficult concepts in multiple ways for different audiences or levels  
•   	Teaching students how to use AI in economics.

   
*Source: Goldsmith-Pinkham (2024); Ransom (2024) Substack; Korinek JEL (2023) writing section*  
 

**Session 5: Productivity and Workflow Automation**  
Beyond specific research tasks, AI can transform the overall academic workflow. This session covers the broader productivity uses that do not fit neatly into other categories — correspondence, project management, and automating the administrative overhead of academic life. It is also a natural place to reflect on how AI tools are evolving and how to stay current.  
 

## **Key Tasks Where AI Can Help**

•   	Drafting correspondence: emails, referee responses, grant text, and cover letters  
•   	Creating and maintaining project documentation: CLAUDE.md files, READMEs  
•   	Using Claude Projects to maintain context across a long research project   
•   	Managing refereeing process: summarizing papers, structuring reports, tracking revisions  
•   	Staying current with journal practices: refereeing, disclosure statements, etc.  
•   	Preparing for seminars and conferences: auto-summarizing your own papers for slides and discussions  
•   	Staying current as tools evolve: Korinek’s JEL update series, Ethan Mollick, Panjwani’s YouTube  
   
*Source: Ransom (2024) Substack; Goldsmith-Pinkham (2024); Korinek (2024) on promoting research*  
   
**Session 6: Literature Review, Research Ideation, Academic Writing**  
AI can now conduct literature reviews autonomously in minutes rather than weeks. This session covers using Deep Research agents — a key example of agentic AI in practice — alongside specialized tools and AI for developing new research ideas. AI is also an excellent editorial assistant throughout the paper-writing process — from structuring arguments to fixing LaTeX errors to managing citations. This session also focuses on integrating AI into the writing workflow without losing your own voice.  
 

## **Key Tasks Where AI Can Help**

•   	Deep Research agents: submitting a research question and receiving a cited literature review in under an hour  
•   	Specialized tools (?): Elicit, Consensus, Connected Papers, and Semantic Scholar  
•   	Using AI to identify gaps in the literature and related empirical strategies  
•   	Brainstorming research questions, model mechanisms, and identification strategies  
•   	Using reasoning models for multi-step theoretical problems and proofs  
•   	Improving clarity, flow, and conciseness: using AI as an editorial tool, not a ghostwriter  
•   	Fixing LaTeX compilation errors, identifying missing packages, and debugging tables  
•   	Automating BibTeX entry creation from journal metadata, DOIs, or screenshots  
•   	Getting pre-submission feedback: prompting AI as a harsh mock referee, Refine.ink  
•   	Using Claude Projects to maintain paper context persistently across sessions

   
*Source: Korinek (2024) NBER WP 33198; Korinek (2025) Table 1 and Section 3.2; Korinek JEL (2023) ideation section; VoxDev slides (2026), Ransom (2024) Substack*

# **A Few Honest Caveats**

•   	AI is most reliable for well-defined, verifiable tasks — code that runs, LaTeX that compiles, text that reads clearly. It is less reliable for factual claims about the literature.  
•   	Always verify citations. AI tools — including Deep Research agents — can hallucinate references that look plausible but do not exist.  
•   	In multi-step agentic workflows, errors can compound undetected. Treat AI agents like a smart research assistant: plan carefully, supervise during execution, and vet the final output.  
•   	Disclosure norms are still evolving. Check your institution’s policies and relevant journal guidelines before submission.
